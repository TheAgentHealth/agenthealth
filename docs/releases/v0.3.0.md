# AgentHealth v0.3.0 — A2A health checks

AgentHealth now validates A2A 0.3.0 JSON-RPC peers through `ping`, `check`, and
`doctor`. Existing HTTP/API and MCP functionality remains available.

- Discovery: bounded agent card retrieval from the standard well-known path
  or a configured card URL, with required metadata and MIME mode validation.
- Protocol and authentication: passive, read-only `tasks/get` requests with
  fresh random IDs validate the advertised JSON-RPC endpoint and credential
  acceptance. ID generation failures return an inconclusive health result.
- Capability expectations: required skill IDs and advertised boolean
  capabilities; missing requirements yield `DEGRADED`.
- Minimal interaction: explicit `functional` opt-in, `safe: true`, and a
  configured text prompt send one `message/send` request without retries.
  Completed tasks and valid agent text replies pass; failures, authentication
  requirements, and pending work use the existing health classifications.
- Safety: same-origin discovered endpoints, verified TLS, no redirects,
  environment credential references, bounded bodies, cancellation, and
  canonical diagnostics without agent output or raw errors.
- Documentation, examples, schemas, and valid/invalid fixtures now cover
  Phase 6 and the new `a2a` configuration options, with passive, bearer,
  custom-card, and functional peer examples.

## Installation and examples

Download the archive for your platform from this release, verify it against
`checksums.txt`, extract it, and run `agenthealth version`.

```bash
agenthealth ping a2a https://agent.example.com
agenthealth doctor a2a https://agent.example.com
agenthealth check examples/a2a-check/agenthealth.yaml --format json
```

See [installation](https://github.com/TheAgentHealth/agenthealth/blob/v0.3.0/docs/installation.md),
[A2A configuration](https://github.com/TheAgentHealth/agenthealth/blob/v0.3.0/docs/a2a-adapter.md),
and [examples](https://github.com/TheAgentHealth/agenthealth/blob/v0.3.0/examples/README.md).
Example endpoints require your own services and matching skill expectations.

## Compatibility and limitations

No breaking changes or migration are required for existing HTTP/API and MCP
configurations. Configuration and result contracts remain `v1`. A2A options
are additive. This software remains pre-1.0.

A2A support is limited to 0.3.0 JSON-RPC. Other A2A versions, REST/gRPC,
streaming execution, push delivery, extended cards, OAuth acquisition, and
remote registries remain future work. Authentication checks establish
acceptance for the passive lookup, not authorization for every skill.

Operators must select a non-destructive functional prompt; `safe: true` is
an operator assertion. There is no task polling, continuation, or automatic
cancellation. Completed interactions do not validate answer semantics.
Local protocol-server tests do not establish interoperability with every
external A2A implementation. Other adapters, SDKs, containers, and Kubernetes
integrations remain planned.

Downloads cover Linux AMD64/ARM64, macOS AMD64/ARM64, and Windows AMD64.
Linux AMD64 receives runtime smoke tests; other platforms are cross-compiled.
Binaries are unsigned; signing, notarization, and SBOM publication remain
future work.
