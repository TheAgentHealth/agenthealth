# AgentHealth v0.13.1 — Python SDK

v0.13.1 publishes the Phase 15 Python SDK and includes the merged stabilization
changes. All distributions share this software version and immutable source tag;
AHS and experimental AHP contracts remain v1.

## Staging correction

The v0.13.0 workflow was stopped before PyPI or the final GitHub Release
published: post-download verification found that the embedded INSTALL.md still
pointed to v0.12.0. The immutable v0.13.0 tag and staged artifacts are preserved.
This patch renders installation references for the exact archive version and
updates stale planned-SDK prose. Existing Go health behavior is unchanged.

## Changes

- Python 3.10+ sync/async checks, typed health/dependency/graph evidence,
  bounded JSON/YAML configuration loading and fixed tool-error exceptions.
- Explicit matching CLI version; no automatic binary download. Go retains
  adapter execution, health aggregation, safety policies and semantic validation.
- Wheel and source archive join GitHub Release downloads, checksums, signed
  provenance and the GHCR OCI binary bundle. Identical artifacts publish to
  PyPI with OIDC trusted publishing and PyPI attestations.
- Stabilization adds explicit passive HTTP GET selection, security/threat-model
  alignment, generated status, coverage/fuzz/profile CI and focused product smoke
  checks. Passive HTTP defaults remain unchanged.
- Kubernetes runtime coverage extends to 1.31.9 and 1.33.1; released/current/
  released checks cover bearer authentication, nested optional failures, graph
  metadata, agent capabilities and gateway/router HTTP signals.

## Compatibility and limitations

Existing v1 configurations and exits remain compatible; explicit passive GET
requires this newer CLI. The SDK requires exactly matching software versions
and returns health failures instead of raising them. Configuration is trusted
executable input. POSIX cancellation terminates stdio descendants; Windows
termination covers the CLI, so detached stdio descendants require lifecycle
controls. Runtime evidence does not establish cloud-cluster certification,
route decision correctness, full framework migration or an external security audit.
Native executable signing/notarization, Operator/CRDs and scoped tenant
authorization remain planned. Experimental AHP retains its documented boundary.

See the [SDK guide](../python-sdk.md), [Phase 15 alignment](../phase-15-alignment.md)
and [stabilization evidence](../stabilization-validation.md). Verified package
digests are appended by the release coordinator after publication jobs succeed.
