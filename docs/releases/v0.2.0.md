# AgentHealth v0.2.0 — MCP health and OAuth preview

AgentHealth now checks MCP servers over Streamable HTTP and configured stdio,
with passive discovery, explicit safe tool probes, and OAuth token acquisition.
Existing HTTP/API checks, result formats, and automation exit codes remain available.

- Protocols: legacy initialization for 2025-03-26, 2025-06-18, and 2025-11-25;
  stateless 2026-07-28 discovery and request metadata, with automatic selection
  or explicit version pinning.
- Discovery: tools, resources, and prompts; required inventory checks report
  missing capabilities as `DEGRADED`.
- Functional checks: explicit opt-in, configured safety declaration, server
  read-only/non-destructive annotations, and required content-field validation.
  Legacy SSE responses can resume with bounded GET requests without repeating
  the tool invocation.
- Stdio: configured command/arguments, selected environment references,
  bounded messages, deadline handling, and process cleanup.
- OAuth: client credentials, refresh tokens and rotation, and authorization
  code + PKCE through the new `login` command. Private token files, per-target
  credential caching, and dynamic secret redaction protect acquired credentials.
- CLI: `doctor <type> <endpoint>` is available alongside configuration-based
  doctor. README, specifications, roadmap, and example configurations cover
  phases 0–5.

## Installation and examples

Download the archive for your platform, verify it against `checksums.txt`,
extract it, and run `agenthealth version`.

See [installation](https://github.com/TheAgentHealth/agenthealth/blob/v0.2.0/docs/installation.md),
[MCP configuration](https://github.com/TheAgentHealth/agenthealth/blob/v0.2.0/docs/mcp-adapter.md),
and [examples](https://github.com/TheAgentHealth/agenthealth/blob/v0.2.0/examples/README.md).
Example endpoints, OAuth clients, and stdio commands require your own services.

## Compatibility and limitations

The configuration/result contract remains `v1`; existing HTTP/API configurations
require no migration. Custom Go adapter integrations should review the added
request environment, run state, and secret-registration fields. This is a pre-1.0
preview; Go APIs and configuration may change in future minor releases.

Deprecated separate HTTP+SSE transport, dynamic OAuth client registration,
JWT client assertions, scope escalation, and interactive tool continuations are
not implemented. A2A and other adapters, SDKs, and container/Kubernetes
integrations remain planned. Functional calls never repeat the invocation.
POSIX stdio cleanup uses process groups; other platforms terminate the direct
child only.

Downloads cover Linux AMD64/ARM64, macOS AMD64/ARM64, and Windows AMD64.
Linux AMD64 receives runtime smoke tests; other platforms are cross-compiled.
Binaries are unsigned; signing, notarization, and SBOM publication remain future work.
