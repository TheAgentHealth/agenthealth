# AgentHealth v0.22.0

Phase 24 adds `agenthealth conformance test <result.json>` for bounded offline
AHS v1 evidence validation and a mandatory reference behavioral suite. It checks
shape, required fields and status/dependency semantics without executing input
or echoing its contents. The source suite records required engine, adapter,
agent/path, graph, AHP, export and executable-transport regressions in JSON.
See the [guide](../conformance.md), [examples](../../examples/conformance/README.md)
and [all-phase alignment](../phase-24-alignment.md).

## Installation and distributions

Publication is pending until the Release workflow and public verification
complete. All implemented distributions use v0.22.0: five platform CLI archives,
five CycloneDX SBOMs, four DEB/RPM packages, channel manifests, Docker image,
Helm chart, OCI binary bundle, Python wheel/source archive and npm tarball.
CLI and SDK versions must match. See [installation verification](../installation.md#verify-provenance-and-sboms)
and [distribution policy](../distribution.md).

```bash
docker run --rm ghcr.io/theagenthealth/agenthealth:v0.22.0 version
pip install agenthealth==0.22.0
npm install @theagenthealth/agenthealth@0.22.0
helm install agenthealth oci://ghcr.io/theagenthealth/charts/agenthealth --version 0.22.0
helm install agenthealth https://github.com/TheAgentHealth/agenthealth/releases/download/v0.22.0/agenthealth-0.22.0.tgz
oras pull ghcr.io/theagenthealth/agenthealth-binaries:v0.22.0
```

OCI binary retrieval uses an artifact client. Helm uses chart version `0.22.0`,
app version `v0.22.0` and image `ghcr.io/theagenthealth/agenthealth:v0.22.0`.
Tagged [manifests](https://github.com/TheAgentHealth/agenthealth/tree/v0.22.0/deploy/kubernetes),
[chart](https://github.com/TheAgentHealth/agenthealth/tree/v0.22.0/deploy/helm/agenthealth)
and [examples](https://github.com/TheAgentHealth/agenthealth/tree/v0.22.0/examples/kubernetes)
share that source. CI requires Kubernetes 1.31.9 and 1.33.1 interoperability
jobs and the disposable Helm/runtime gate; actual outcomes belong in the
publication verification record.

## Compatibility and migration

No AHS/AHP v1 fields, health states, adapter interfaces or existing health exits
change. Existing configurations require no migration. Conformance returns 0 for
valid evidence and 6 for invalid evidence/tool failure, independently of target
health. SDK wrappers retain their existing APIs and adopt the shared version.

## Limitations

The offline command accepts regular UTF-8 JSON result files only, up to 4 MiB and
64 dependency levels. Only v1 and current AHS dimensions are supported; it does
not validate AHP envelopes, YAML, configurations or export payloads. Static
evidence cannot establish runtime safety, truthfulness, current health or complete
secret removal. The behavioral suite exercises reference source with controlled
fixtures; independent product matrices, audit, OS isolation, native executable
signing and certification remain separate work. Local Windows Application Control
prevented Go formatting/vet; CI validation is required before publication.
